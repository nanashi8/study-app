# 全教材監査の管理方法

## 目的

「監査したはず」を担当者の記憶や一度きりのターミナル出力にしない。学習者に公開する全教材の母数、実施した監査、結果、監査対象データ、監査コードを、再検証できる形で残す。

## 管理するデータ

`docs/audits/content-audit-ledger.json`を監査台帳の正本とする。対象母集団は`LEARNING_CONTENTS`に登録された全18教材カテゴリで、台帳には次を保存する。

- 教材カテゴリごとの学習項目数・出題項目数・ID順ハッシュ・内容ハッシュ
- 各カテゴリに適用した品質ゲート、そのコマンド、監査範囲
- 保存済み／生成済み問題バンクごとの問題数・選択肢数・正答一意性・問題別解説数・選択肢別解説数
- 文法3,450問の生成／入試型／手動内訳、13,800選択肢、17,250回答経路、和訳表示区分、失敗件数
- 共通講師解説を使う英単語・熟語・文法・古典・リスニング・長文・診断・数学について、正解・全誤答・「わからない」に返す回答別指導の教材別経路数
- 監査日時、実行コマンド、監査コードとテスト一式のハッシュ、失敗ID

件数だけが同じでも、内容または監査コードが変わればハッシュが変わる。`npm run check`は台帳の陳腐化を失敗として扱う。

## 監査と記録

内容を変更したら次を実行する。

```sh
npm run audit:all-content
```

このコマンドは、全テスト、全教材品質ゲート、GitHub Pages配備先検査、Viteビルド、公開物の秘密情報検査、差分の空白エラー検査を順に実行する。途中で一つでも失敗した場合は、合格台帳を更新しない。すべて成功した場合だけ監査時刻と現在の母集団ハッシュを記録する。

通常の確認は次で行う。

```sh
npm run audit:content-ledger
```

## 合格の読み方

台帳の`result: "pass"`は、`auditGates`と各カテゴリの`auditGateIds`に明記された観点が全件合格したことを表す。監査していない観点まで合格したとは扱わない。

問題別の一般解説と、4択それぞれの根拠は別々に数える。今回の英文法は全4択の根拠を監査対象にする。他教材に選択肢別解説がない場合、`generalRationaleCount`は増えても`choiceSpecificRationaleCount`は0のまま残るため、管理画面上の数字で区別できる。
