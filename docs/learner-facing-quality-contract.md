# 学習者向け表示・解説の品質契約

## 目的

過去に修正した表示、解説、保存導線を、担当者の記憶だけに依存させず再違反から守る。この文書を判断記録、`scripts/check-learner-facing-contract.mjs` を機械的なリリースゲートとする。

## 日本語案内の全件監査

- 学習者が読む案内は、`src`内の全JSX、画面文を作る`src/lib`全体、入口名を持つ`src/data/contents.js`を対象にする。教材本文・訳・単語の意味は、教科上必要な表現を壊さないため別の教材監査で扱う。
- `npm run audit:japanese`は、対象231ファイルの日本語12,624表記（重複なし9,977表記）をすべて読み、禁止した短縮語・内部用語・事務的な表現を行番号付きで検出する。参考として`src`全体552ファイルの日本語114,557表記も数える。
- 新しい案内を追加したときも、見出し、ボタン、補足、`aria-label`、自動生成される助言を同じ監査に含める。検出0件でなければ完了としない。
- `最新が「…」`のように主語が欠ける文、`1セッション`、`SRS`、`スナップショット`のような内部語、`三手`のような独自の短縮語は使わない。何の結果か、本人が次に何をするかを文で示す。
- 結果画面は、共通結果へ進む7経路と専用結果を持つ14経路の計21経路を固定母数とする。全経路で、本人が実際に答えた内容と次の行動を直接示し、内部の段階、間隔の変化、予測値を成果として表示しない。

## 問題中の移動と自動送り

- 問題数を選べるテスト・暗記の全18画面は、問題の上に共通の`前へ／数字進捗／次へ`を1本のバーで置き、進み具合はそのバーの下端に細く示す。最初・最後では進めない方向を無効にし、44px以上の押せる範囲と読み上げ名を持たせる。途中でやめる操作は上部の共通`戻る`に任せ、このバーに`×`を重ねない。
- 正誤をすぐ示す全11テストは、同じ上部操作内に`正解したら自動で次へ`を表示する。初期状態はオン、設定は既存の端末保存・進捗コード・クラウド同期の契約を通す。
- 正解後の自動送りは1.4秒待ち、解説を読める時間を残す。最後の問題では結果へ進む。オフに切り替えた場合はその場に残る。
- 前後に移動しても各問題の回答表示を保持し、回答済み問題を見直しても正答数、自己評価、復習記録を二重計上しない。やり直しを選んだときだけ今回の回答履歴を消す。
- 答えた問題へ前へ戻ったときは、答えを選び直せる（テストは選択肢と`わからない`、暗記は`覚えた／まだ`、並べ替え・書き取り・返り点は`並べ直す`）。選び直した答えは、その問題の最初の答えを置き換え、復習記録・正答数・`覚えた`数・学習分析の正解数を二重に数えない（回答数と学習時間は最初の回答のまま）。答えた直後のその場では、これまでどおり確定のままにする。
- 数字進捗から1回の問題数（カード数）を、答えた問題より少なく選んでも、答えた分の復習記録と正解数・`覚えた`数などの集計は消さない。答えた問題は結果の全問数に含めたまま、まだ答えていない問題（表示中の問題から）を1問目として数え直す。`破棄されます`の確認は出さない。
- 画面下部の回答操作は、その問題の答えを確定して次の未回答問題へ進むために残す。上部操作は、回答済みの問題を前後に見直すために使う。

## 解説の意味契約

- `根拠`は、その設問固有の英文、説明、条件、数値または本文箇所を含める。一般論だけにしない。
- `消去法`は、選択した誤答を明示し、その問題では成立しない理由を先に示す。形が成立する条件を補足する場合も、別条件の紹介だけで終えない。
- `考え方`は、同じ単元の次の問題にも使える判定順を示す。「答えを覚える」だけの指示にしない。
- 正答、全誤答、`わからない`の全経路を監査対象にする。見本だけで全件完了としない。
- 文法問題は、問題文の空所位置、必要な意味、適用規則、正答を入れた完成文、残りの選択肢が外れる条件を順に示す。「この規則だから」だけで問題文との接続を省略しない。
- 選択式の出題は「3択＋わからない」でそろえる。教材データは誤答ごとの根拠をそろえるため4択のまま保ち、出題時に`limitQuizChoices`で正解＋誤答2つへ絞る（問題IDから決まるので、同じ問題はいつ解いても同じ3択）。
- 文法の`選択肢解説`は出題した3択すべてを表示し、各択に「この文で正しい理由」または「この文では成立しない理由」と、その形を使える別条件を分けて示す。画面に出していない誤答は「残りの選択肢」に含めない。
- 英文だけでは意味の異なる複数の選択肢が成立し得る問題は、和訳を設問条件として解答前に`判断に必要な意味`で示す。活用形など英語の形だけで一意に決まる問題では、解答前の和訳を答えのヒントにせず、答え合わせ後に完成文とともに示す。
- 文法の選択肢は、宣言された`answer`が一件あるだけでは合格にしない。文頭命令表現など、英文上で複数が成立する組み合わせを別ゲートで検出し、問題文と必要な意味を合わせても正答が一つになるよう選択肢を直す。

## 全教材監査台帳

- 全18教材カテゴリの母数、問題バンク、監査ゲート、合否、データハッシュ、監査コードハッシュを`docs/audits/content-audit-ledger.json`に保存する。管理方法は`docs/content-audit-management.md`を正本とする。
- `npm run audit:all-content`は、全テスト、全教材ゲート、ビルド、公開物検査、差分検査がすべて成功した場合だけ台帳を更新する。途中失敗時に合格記録を残さない。
- `npm run audit:normal-learning-record-lists`は、通常入口8/8、熟語1,754・構文350・古文単語300・古文文法74・古文常識56・漢語120・漢文法87・漢文常識95の計2,836/2,836項目を固定母数とする。通常画面そのものへの共通一覧配置、学習／テスト切替、左右スワイプ、再表示、既存SRSへの4結果の書き込み先、公開入口を全件検査し、別の記録画面だけに実装しても合格させない。
- `npm run check`は現行教材または監査コードと台帳のハッシュが違えば失敗する。内容変更後に古い監査結果を流用しない。
- 問題別の一般解説と、選択肢別の根拠を別の数で管理する。一般解説が一件あることを「全選択肢を説明済み」と数えない。

## 重複を出さない契約

- Readerの原文英語、隣接する日本語、必要な読み方の説明は、`meaningPhraseSequence`で一度だけ表示・再生する。
- 下段の`文法解説`は同じ意味フレーズを再掲せず、節・句の役割、内部順、まだ表示していない読み方・文法上の注意だけを示す。
- 同一文内で完全に同じ説明が複数回生成された場合は最初の一回だけ表示・再生する。長い一文の`note`と`roleNote`も同じ基準にする。
- 文全体の自然な和訳は最後に置き、前から読む対応日本語と混ぜない。

## 語源の説明契約

- 全収録語について、既存の語源史実を変えずに`作られ方`、`もとの形・言語`、`意味の変化／由来の記録`、`今の意味`を欠けなく表示できるようにする。
- 学習者向け画面では`現在義`、`共通軸`、`記載上の出発言語`、`濃縮パック`を見出し語として使わない。必要な厳密さは平易な説明文で補う。
- 語源トップは語根そのものの`暗記`・`テスト`・`一覧を確認`をそろえる。語源カードを1枚開いた画面には語根1つだけの暗記・テストを置かず、紐づく単語の`暗記`・`テスト`を英単語と同じ画面で行う。廃止した2択の正誤問題と旧`単語クイズ`は公開導線へ戻さない。
- 紐づく単語を覚えた結果は単語SRSへ、語根そのものの暗記・テストは語源専用の`etymologySrs`へ記録する。どちらも進捗コードとクラウド同期に載せ、過去データもそのまま読み戻す。
- 同じ語根でない語を同根と断定せず、分かっている形成・言語・意味分野の共通点だけを示す。

## 出題の真偽契約

学習者が「教材の通りに答えたのに不正解」になる状態を作らない。次の5点を機械が守る。直したときは必ず、わざと壊して落ちることを確かめてから通す。

- **誤答は正解と同じ意味であってはならない**（`scripts/english-content-audit.mjs`）。表記ゆれを潰した上で、誤答の代表義が正解の全語義に含まれる／その逆を禁じる。単語・熟語・構文の両方を、実際の出題乱数で再現して検査する。`pickDistractors` / `pickPhraseDistractors` 側の守りとは独立に書き、二重にする。
- **先頭の語義に別品詞の注記を付けない**（`scripts/check-data.mjs`）。先頭語義はテストの答えであり品詞バッジが指す意味でもあるため、`計画(名)・投影する` のような形は並び順か `pos` の誤りとして落とす。
- **so...that の結果節と従属節の主語に立つ代名詞は、文の主語と性が一致する**（同上）。`Ken sent her a birthday card.` のように別人を指す目的語は対象にしない。
- **人を主語に天候の形容詞を使わない**（同上）。`Ken was so dark that ...` のような総当たり生成の破綻を止める。
- **読解の疑問詞と答えの型をそろえる**（同上）。When なら時、Where なら場所、How many/much なら数量を答える。Why の型ずれは機械で拾えないため、Why問題は追加・変更のたびに全問読む。

漢文の訓読は、読む順が書き下し文と同じ並びになっていること（`scripts/check-data.mjs`）。書き下しに現れる漢字は読む順と同じ相対順序で出るはずで、食い違えば正しく並べた学習者と書き下し文が矛盾する。再読文字は①②で二度置き、二度目は照合から外す。

古文の条件表現は、未然形＋ば（仮定「〜なら」）と已然形＋ば（確定「〜ので・〜すると」）を取り違えない（`scripts/check-data.mjs`）。ア段のかな＋ばはどの活用でも已然形になりえないので、そこを機械で落とす。

古文単語は用例と現代語訳を必ず対で持つ（`scripts/check-data.mjs`）。用例の使い回しも落とす。これまで一件も検査が無く、300語のうち107語が用例なしのまま公開されていた。古典文法問題の誤答は、正解の一部を丸ごと含んではいけない（「連用形接続」を「連用形接続（カ変・サ変には特殊な接続あり）」の誤答に出さない）。

由来のちがう別語が同じつづりになっただけの語は、代表義の欄をいっしょにしない（`scripts/check-data.mjs` と `src/data/homographs.js`）。1見出し1枚のカードに両方の意味を並べると、語源の説明が片方にしか当てはまらず、学習者は誤った由来を教わる。実際に bank の意味欄へ「土手」を並べたまま「イタリア語 banca（両替商の台）」とだけ説明していた。別語の意味は `word-senses.js` へ `separateWord: true` と、どう別の語かを書いた `note` を付けて置き、カードでは「同じつづりの別の語」として代表義と分けて見せる。何が別語かは語源の判断なので台帳に人が書き、混入の検出だけを機械に任せる。まだカードに載せていない語（fair, tear, mine, lead, sound など）も先に台帳へ載せ、あとから混ぜるのを止める。kind の「親切な／種類」のような同じ語の枝分かれは台帳へ入れない。

同じ語の単数形と複数形を、意味の重なる別カードとして登録しない（`scripts/check-data.mjs` と `src/data/duplicate-forms.js`）。覚え具合は1見出しに1つなので、同じことを二度覚えさせるうえ、片方の代表義がもう片方の誤答に出て「正解なのに不正解」になりうる。別見出しを立ててよいのは、その形でしか出ない意味があるときだけ（manners=作法、arms=兵器、goods=商品、glasses=めがね、economics=経済学、ethics=倫理学、brains=知力）。**それが辞書の判断であることが要点で、意味欄の重なり方からは決められない**——fee「料金・謝礼」と fees「料金・手数料」は文字列としては一部しか重ならないが、複数形固有の意味は持っていない。そこで正当な複数形は `PLURAL_ONLY_SENSES` に人が書き、検査は「意味が一つでも重なったらどちらかの台帳に載っていること」を求める。重複していた20組のうち18組は見出しを畳んだ。手動確認済みの語源カード13枚はどれも単数形を同じ欄に持っていたので、教材は一つも欠けていない——指紋を押し直す前に、変化が「消した複数形の除去だけ」で説明できることを旧の指紋を再現して確かめる。残る2組（grapes / socks）は英検1900語の収録リストが複数形を挙げ、長文が単数形を使うので、どちらの形も別の教材から名指しで要る。検査は台帳に無い重複、直ったのに台帳へ残り続けている組、両方の台帳に重ねて載せた組、そして**単数形に無い意味を実際には持たないのに複数形固有だと書いた組**を落とす。

単語の級(level)は、ほかの教材と食い違わせない（`scripts/check-word-levels.mjs`）。級は学習の順番そのもので、間違えると5級の学習者に準1級の語が出たり、同じ語を二つの級で二度覚えさせたりする。機械には「正しい級」は決められないので、食い違いだけを2つ見る——**英検1900語の収録リストが級を挙げている語はその級で出す**、**その級より3段以上やさしい英文（長文・書き取り・リスニング・熟語）に同じ語が出ていない**。後者は派生形カードが基語の活用形と綴りを共有する場合（closing は close の -ing）を除く。

級そのものは `src/data/levels-override.js` が持つ。この表は一括指定を含んでいて、v/w/y/z の語がほぼ丸ごと3級に入っていたことがある（zeal, womb, venom, vessel, wrench …）。級を足すときは一語ずつ判断し、**その級以下の英文に本当に出ない語かを確かめてから**入れる。級ごとの累積語数（5級606 / 4級1303 / 3級2102 / 準2級3528 / 2級5105 / 準1級7878）が英検の公表語彙数から大きく外れたら、一括指定を疑う。

単語の例文は必ず見出し語そのものを使う（`scripts/check-data.mjs`）。ethnicity の例文が ethnic だけを使うような形は、何を覚えるのか示せないので落とす。複数語・ハイフン付きの見出しは記号を空白に均して並びで、1語の見出しは規則変化と不規則形の表で照合する。

単語の例文は、その語が使われる場面を一文で見せる（`scripts/check-data.mjs`）。`a loquacious guide`（話好きなガイド）のような句だけの例文では、どう使う語なのか、どんな場面で出会う語なのかが伝わらず、読み上げても文にならない。英文は大文字で始まり `.` `?` `!` で終わる一文、和訳も「。」「？」「！」で終わる一文にし、`Thus, we conclude that...` のような言いさしも落とす。略語の点（Mr. / Mt. / a.m.）では文を区切らない。長文辞書語は本文の一文と本文の和訳をそのまま引くため、本文の和訳が2文に分かれていても和訳の一文検査からは外す。

テーマ別英作文は、各手順のおすすめの選択肢をちょうど1件に保つ（`scripts/check-data.mjs`）。0件だと画面から助言と文法カードが消え、2件以上だとどちらを指すか決まらない。手順id・選択肢id・選択肢の英文の重複も落とす。

和文英訳は、和文の順に訳した正しい英文を不正解にしない（`scripts/check-data.mjs`）。採点は模範解答と別解への完全一致なので、和文が従属節から始まる問題は、受理できる形のどれかも従属節から始めておく。`so 〜 that` や `So + 形容詞`の倒置のように英語側で主節が先に決まる型、副詞句へ畳み込む型（`none the less for` など）は対象外。

数学クエストの誘導ステップは「答えられる形」を保つ（`scripts/check-data.mjs`）。空所の正解は必ずタイルに含め、誤答のタイルも1枚以上残す。式の□の数と答えの数をそろえ、タイルの重複と選択肢の範囲外を落とす。問題文(text)と数式(prompt)はどちらも任意だが、両方無いと問題欄が空になるため片方は必須。

書き取る英文は1文として完結させる（大文字始まり・句点終わり）。ディクテーションの語数は本文から導出しているため、記載値との突き合わせは常に一致し検査にならない。

## 共通メニューと保存

- `AppShell`上部には共通`戻る`、現在のアプリ名、一つの`メニュー`ボタンを置き、全公開画面が同じ入口を使う。下部に重複するナビを置かない。
- 上部の`メニュー`は全教材、検索、診断、保存一覧、学習記録とおすすめ、設定、履歴リセットへ到達できる共通シートを開く。
- `暗記・テストの記録`はメニューの`保存・記録`に置き、全18教材の暗記状態とテスト結果を教科ごとに確認できる画面とする。入口表記は`一覧を確認`に統一する。英単語、熟語・構文、古文単語、古文文法、古文常識、漢語、漢文法、漢文常識は、学習前・テスト前を含む全項目を学習／テスト別に表示し、チェック式選択と開始フッターを置かない。学習側は`学習前／覚えた／まだ`、テスト側は`テスト前／正解／不正解`を示す。左スワイプで`覚えた／正解`、右スワイプで`まだ／不正解`を既存SRSへ毎回追加する。英単語の行をタップすると単語詳細を開き、ほかの対象教材ではその1項目の学習を始める。処理した行はその一覧から一時的に隠し、`一覧を再表示`で同じ対象を戻して、カードを始めなくても連続スワイプでまとめて学べるようにする。通常時の操作欄は教材、学習／テスト、スワイプ案内と再表示の3段程度に収め、検索・並び替えは開閉式にして一覧を画面の主領域にする。それ以外の教材は全項目を検索し、最終学習日、最終テスト日、分野、先に復習する順で並べ替え、選択した項目を既存の学習画面で学べるようにする。全一覧では右スワイプで学習項目へ追加し、左スワイプで再表示しない設定にする。学習項目の一覧では右スワイプで取り組む順番を上げ、左スワイプで一覧から外す。非表示の一覧から全一覧へ戻せ、これらの設定は学習ノートと同じ保存・同期・リセット契約を通す。保存一覧は専用画面へ分け、同じ内容を重複表示しない。
- 熟語・構文、古文単語・古文文法・古文常識、漢語・漢文法・漢文常識は、それぞれの通常の教材入口でも、同じ学習／テスト切替、状態表示、左右スワイプ、処理後の一時非表示、一覧の再表示を使えるようにする。通常入口と記録画面は同じ既存SRS書き込み口を共有し、どちらで記録しても端末保存、進捗コード、クラウド同期、リセット、学習記録の表示に同じ結果が出るようにする。
- メニューは`スタディアプリ`、`英語の学習`、`学習サポート`、`保存・記録`、`設定・アカウント`の見出しで整理し、見出し自体を別メニューへの入口にしない。`スタディアプリ ホーム`を含む全項目を同じ画面から直接選べる一段構造にする。全29項目は`APP_MENU_SECTIONS`を一つの台帳として扱い、公開ルート、重複、欠落を全件監査する。
- 暗記・テスト・読解の途中で上部`戻る`を押した場合は、確認を挟まずそのまま前の画面へ戻す。進捗を破棄せず、答えた1問ごとの記録に加えて、そこまでに答えた問題数と正解数をその分野の学習記録へ残す。`進捗は破棄されます`という確認は表示しない。
- 共通結果へ進むテスト5画面（英単語、熟語・構文、リスニング、書き取り、文法）は、最後まで進んだときだけ結果画面が結果を数え、途中でやめたときは画面を離れるときに答えた分だけを一度数える。辞書・詳細を開くために続きを退避した場合は数えず、戻って続きから記録する。二重に数えない。
- 英単語の暗記（`今日の復習`を含む）は1枚答えるごとに記録するので、途中で上部`戻る`を押しても答えた分は復習予定に残る。暗記・テストの進捗バーには、上部`戻る`と同じ働きの`×`（やめる）を置かない。最後まで答えた回は学習結果へ進み、結果の`今回`と`今回学んだ語`は答えたカードだけで数える。
- 級・分野の暗記は、今日の候補（未学習・復習どき）を先に出し、出し切ったあとは同じ教材の残りを`まだ`と答えた語から順に続けて出す。級・分野カードの`暗記`は語がある限り押せる状態に保ち、`次回待ち`で止めない。結果画面の`次の◯語へ`も、同じ教材を一巡するまで続ける。
- 上部中央のアプリ名は保存確認を開かず、そのアプリのホームへ直接戻す。途中からメニューで`スタディアプリ ホーム`へ移動する場合は、保存確認を必ず挟む。
- 確定済みの学習結果は端末へ自動保存する。確認画面では、同じ永続スライスをQR画像または`EQ1-`コードとして出力できるようにする。
- 端末保存、進捗コード、クラウド復元、学習記録画面は、`PERSISTED_PROGRESS_FIELDS`と`selectProgressState()`を唯一の項目契約として共有する。
- 学習履歴のリセットは、ブラウザの履歴削除と同様に`すべて選択`と分類別チェックを同じ画面に置く。分類は、復習の記録と予定、学習を終えた記録、診断・テスト結果、保存教材、辞書履歴、旧版互換記録の6つとする。
- `PERSISTED_PROGRESS_FIELDS`の全48項目は、6分類でリセットできる45項目か、常に保持する`settings`、`portalOrder`、`portalHidden`の3項目のどちらか一方に必ず属する。分類漏れ、二重分類、未知項目をリリースゲートで失敗させる。
- 部分リセットは選択分類だけを初期化し、非選択分類と進行中セッションを変更しない。全選択時だけ進行中セッションも終了する。実行前にQR・コードでバックアップでき、ログイン中は遅延自動保存を待たず選択後の全状態をクラウドへ書き込む。

## 適用中の既往ルール

- `全問題`、`すべて`という依頼では、対象総数、対象ルート、監査方法、完了条件を先に固定する。
- 長文音声は原文英語、隣接する前からの日本語、必要な項目別説明の順にし、自然訳は最後に置く。表示用の括弧記号は読み上げない。
