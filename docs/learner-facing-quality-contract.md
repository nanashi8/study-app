# 学習者向け表示・解説の品質契約

## 目的

過去に修正した表示、解説、保存導線を、担当者の記憶だけに依存させず再違反から守る。この文書を判断記録、`scripts/check-learner-facing-contract.mjs` を機械的なリリースゲートとする。

## 現行の表示契約

| 対象 | 現行表示 | 廃止した表示・挙動 |
| --- | --- | --- |
| 文法の全選択肢 | `選択肢解説` | `選択肢の使い分け`、状態札 `別の場面で使う` |
| 共通解説の evidence | `根拠` | `根拠を一本化` |
| 共通解説の trap | `消去法` | `誤答を切る` |
| 共通解説の strategy | `考え方` | `次も解ける型` |
| Readerの構造欄 | `長文読解` | `構文の見取り図` |
| Readerのブロック欄 | `文法解説` | `構造を確かめる文法ブロック解説`、`節・句・文法ブロック解説` |
| 英語ホーム | `単語`から級を選び、級画面内で`覚える／クイズ`を選ぶ | 同じ級画面へ進む独立した`クイズ`入口 |
| 語源の4分類 | `部品で分ける`、`同じ語根`、`語の家族`、`ことばの歴史` | `部品の式`、`共有語根`、`語族`、`成り立ち・変化`を説明なしで並べる表示 |
| 単語の語源 | 単語カードでは答えと同時、単語クイズでは解答直後に本文を表示 | `語源をくわしく見る`を押さないと本文が読めない表示 |

## 解説の意味契約

- `根拠`は、その設問固有の英文、説明、条件、数値または本文箇所を含める。一般論だけにしない。
- `消去法`は、選択した誤答を明示し、その問題では成立しない理由を先に示す。形が成立する条件を補足する場合も、別条件の紹介だけで終えない。
- `考え方`は、同じ単元の次の問題にも使える判定順を示す。「答えを覚える」だけの指示にしない。
- 正答、全誤答、`わからない`の全経路を監査対象にする。見本だけで全件完了としない。

## 重複を出さない契約

- Readerの原文英語、隣接する日本語、必要な読み方の説明は、`meaningPhraseSequence`で一度だけ表示・再生する。
- 下段の`文法解説`は同じ意味フレーズを再掲せず、節・句の役割、内部順、まだ表示していない読み方・文法上の注意だけを示す。
- 同一文内で完全に同じ説明が複数回生成された場合は最初の一回だけ表示・再生する。長い一文の`note`と`roleNote`も同じ基準にする。
- 文全体の自然な和訳は最後に置き、前から読む対応日本語と混ぜない。

## 語源の説明契約

- 全収録語について、既存の語源史実を変えずに`作られ方`、`もとの形・言語`、`意味の変化／由来の記録`、`今の意味`を欠けなく表示できるようにする。
- 学習者向け画面では`現在義`、`共通軸`、`記載上の出発言語`、`濃縮パック`を見出し語として使わない。必要な厳密さは平易な説明文で補う。
- 語源画面の学習操作は、英単語と同じ`覚える`画面に一本化する。語源専用の暗記画面・2択・単語クイズは公開導線へ置かない。
- 語源から覚えた結果は単語SRSへ記録する。旧`etymologySrs`は過去データの読込・進捗コード・クラウド同期の互換用として保持し、新しい語源画面から更新しない。
- 同じ語根でない語を同根と断定せず、分かっている形成・言語・意味分野の共通点だけを示す。

## 共通メニューと保存

- `AppShell`上部には共通`戻る`と一つの`メニュー`ボタンだけを置き、全公開画面が同じ入口を使う。下部に重複するナビを置かない。
- 上部の`メニュー`は全教材、検索、診断、保存一覧、分析、設定、履歴リセットへ到達できる共通シートを開く。
- `マイ学習`はメニューの`保存・記録`に置き、英単語だけでなく、保存項目と学習済み項目を教材種類別に再利用できる索引とする。
- メニューは`スタディアプリ`、`英語の学習`、`学習サポート`、`保存・記録`、`設定・アカウント`の見出しで整理し、見出し自体を別メニューへの入口にしない。`スタディアプリ ホーム`を含む全項目を同じ画面から直接選べる一段構造にする。全29項目は`APP_MENU_SECTIONS`を一つの台帳として扱い、公開ルート、重複、欠落を全件監査する。
- 学習・クイズ・読解の途中で上部`戻る`を押した場合は、`進捗は破棄されます`と表示し、`戻る`か`続ける`かを本人が選べるようにする。途中から`スタディアプリ ホーム`へ移動する場合は、保存確認を必ず挟む。
- 確定済みの学習結果は端末へ自動保存する。確認画面では、同じ永続スライスをQR画像または`EQ1-`コードとして出力できるようにする。
- 端末保存、進捗コード、クラウド復元、学習記録画面は、`PERSISTED_PROGRESS_FIELDS`と`selectProgressState()`を唯一の項目契約として共有する。
- 学習履歴のリセットは、ブラウザの履歴削除と同様に`すべて選択`と分類別チェックを同じ画面に置く。分類は、復習段階、学習済み、診断・成績、保存教材、辞書履歴、旧版互換記録の6つとする。
- `PERSISTED_PROGRESS_FIELDS`の全47項目は、6分類でリセットできる44項目か、常に保持する`settings`、`portalOrder`、`portalHidden`の3項目のどちらか一方に必ず属する。分類漏れ、二重分類、未知項目をリリースゲートで失敗させる。
- 部分リセットは選択分類だけを初期化し、非選択分類と進行中セッションを変更しない。全選択時だけ進行中セッションも終了する。実行前にQR・コードでバックアップでき、ログイン中は遅延自動保存を待たず選択後の全状態をクラウドへ書き込む。

## 適用中の既往ルール

- `全問題`、`すべて`という依頼では、対象総数、対象ルート、監査方法、完了条件を先に固定する。
- 長文音声は原文英語、隣接する前からの日本語、必要な項目別説明の順にし、自然訳は最後に置く。表示用の括弧記号は読み上げない。
- 読み上げは共通コンソールの再生、一時停止、前へ、次へ、停止、速度を使う。
- ID、SRS、学習履歴、マイリスト、進捗コード、分析、クラウド同期の互換性を表示変更で壊さない。
- 画面名の変更は、見出しだけでなく入口、一覧、メニュー、プレイヤーラベルも横断検索する。
- コンパクト画面では主要な選択肢を先に見せ、390×844と320×568を確認する。
- 学習評価と表示演出を混ぜない。廃止したゲームBGM、攻撃、HP、勝敗演出を復元しない。
